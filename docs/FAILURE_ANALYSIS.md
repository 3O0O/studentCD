## 2. 把支持不足与选择损失分开

设某条记录的候选集合为 `C`，固定修改位置指标为 `m(y)`，所选候选为 `y_selected`，标签诊断上界为：

$$
m_{\mathrm{oracle}}=\max_{y\in C}m(y).
$$

在同一候选池、同一指标下，有恒等式：

$$
1-m(y_{\mathrm{selected}})
=\bigl(1-m_{\mathrm{oracle}}\bigr)
+\bigl(m_{\mathrm{oracle}}-m(y_{\mathrm{selected}})\bigr).
$$

第一项是在该位置指标下，候选池相对满分尚缺的部分；第二项是已有候选中更好的指标值没有被选择的部分。两项可以同时为正，不是互斥失败类型，也不是因果归因。逐样本恒等式经同一学生等权汇总后仍成立。

已有无代码联表核验了完整 70 条／17 学生的这一分解。均衡池／11-only 池含 copy 的 oracle 学生宏 F1 为 0.472878／0.453251，生成候选 oracle 为 0.387911／0.368284；B 有正选择损失的记录为 51／70 和 55／70。65 条真实改动中，零修改位置支持为 4／65 和 5／65。不能把“有选择损失的记录数”与“零支持记录数”相加当作互斥占比。

这里的 oracle 读取未来标签，只能用于诊断，不能成为预测时的选择器。它衡量的也是修改位置：即使位置完全重合，改动内容仍可能不对；精确下一文本缺失，也不证明没有语义合理候选。强提示候选池缺少同等 oracle 材料，不能补造它们的支持／排序分解。缺少 copy 完整 likelihood 和排名材料时，也不能断言它因哪一个评分项落选。

## 3. 四类手写合成例子

**统一声明：本节代码与反馈全部手写。** 未运行程序、判题器或模型，未计算这些例子的实验 F1、CRPS 或 likelihood。下面的“观察到的下一步”“候选池”“被选输出”都是为讲解而设定的情境，不对应实际记录或真实评分结果。

### 例子一：不改，却被改了

手写当前程序，约定输入为字符串：

```python
def repeat(word):
    return word + word
```

设定下一提交与当前完全相同。假设预测提交却作了下面的改写：

```diff
 def repeat(word):
-    return word + word
+    return word * 2
```

对这个设定，行为真值是不改动，预测却改动。即使两种写法在约定输入上表达相同意图，也没有预测对下一次文本行为。整体字符相似度可能很高，却不能消除误改；功能相似也不等于修订过程相似。

应分别看不改动概率、概率损失、固定决策规则下的误改，以及文本行为指标。如果模型在 95% 会改动的队列上对所有记录都预测改动，总体准确率可以很高，仍然无法识别少数不改动。下一提交缺失则不能放进这个例子所代表的不改动类别。

当前 A 的不改动组只有 copy 一个候选。共同 q 为它分配概率；CD 无法在只有一个候选的组内改善排序。这里需要检查的是 q 与决策规则，而不是仅继续扩大改动候选。

### 例子二：局部修改被变成整段重写

手写当前程序：

```python
def count_positive(values):
    total = 0
    for value in values:
        if value >= 0:
            total += 1
    return total

def first(values):
    return values[1]
```

手写反馈只讨论 `count_positive`：“零不是正数。”设定下一提交仅完成下面的修改：

```diff
-        if value >= 0:
+        if value > 0:
```

假设预测提交为：

```python
def count_positive(values):
    return sum(value > 0 for value in values)

def first(values):
    return values[0]
```

预测既重写循环，还改变了未被当前反馈涉及的另一个函数。对约定的普通整数输入，正数计数的意图与局部修改一致；这仍然不能说明预测忠实于设定的下一行为。我们没有验证 `first` 的任务要求，更不能因它看起来合理就把额外改动叫作真实学生进步。

若只检查建议中的条件是否出现，可能高估反馈采纳；若只看位置重合，可能遗漏代码内容与非目标修改。需要联合看位置／操作的 precision 与 recall、编辑规模分布、反馈目标与非目标区域的变化。保守编辑也不是越少越好：真实学生确实重写时，同样应该保留这种行为的预测空间。

### 例子三：想要的局部修改没有进入候选池

手写当前程序：

```python
def chosen():
    a = 1
    b = 2
    return a
```

设定下一提交只修改返回变量：

```diff
-    return a
+    return b
```

手写候选池只包含三种情形：原样 copy；仅把 `a = 1` 改为 `a = 0`；仅把 `b = 2` 改为 `b = 0`。三个候选都没有修改返回语句。

在这个设定的有限候选池里，仅改变排序不能选出所需局部修改。全文件字符相似度仍可能很高，因为候选与当前只差一行；高相似度不能证明目标行为已经有支持。

诊断必须区分精确文本覆盖、修改位置覆盖与语义覆盖。位置 oracle 是候选范围的事后上界，不是真实生成能力或功能正确性的完整度量。下一步应比较候选生成器或表示是否增加相关修订支持，并单独记录尝试数、重复、截断、token 与成本；不能偷偷插入真实下一提交或按标签补采样。

### 例子四：池里有目标修订，排序却选错

沿用例子三的手写当前程序和下一提交。现在池中加入候选：

```python
def chosen():
    a = 1
    b = 2
    return b
```

同时存在另一个改名候选：

```python
def chosen():
    first_value = 1
    second_value = 2
    return first_value
```

为了讲解，**设定**最后选中了改名候选。这里不宣称实际 CD、B 或基础评分一定会这样选择，也不提供虚构模型分数。

目标文本已经在池里，所以在固定行为指标下存在可避免的选择损失。仅扩大候选数未必解决已有好候选落选的问题，应在同池、相同输入和相同预算下检查排序。

还应注意，两个候选都涉及返回语句所在位置，但返回内容不同。修改位置指标可能对它们给出部分重合，而无法完整表达内容差异。只有位置分数上升，不足以宣称功能、反馈落实或学生行为都改善。功能评价仍须在安全判题验收后另做，不能在本例中以静态直觉冒充测试结果。

## 4. 可证伪机制假设

下面各项是待检验解释，不是已经确定的根因。下一实验应在训练范围内决定特征、权重和控制，先冻结协议，再比较，避免用已见开发案例挑选赢家。

| 假设 | 与它相容的已见证据 | 当前缺少什么 | 有判别力的下一检查／反例 |
| --- | --- | --- | --- |
| H1：q 的低成本特征不能区分少数不改动 | 概率损失较任务频率更差，预测集中于高改动概率 | 37 条的标签含义、任务分布与来源代表性审查；同任务先验的特征增量比较 | 训练学生留出与时间前推下，对共同任务先验增加历史／反馈内容；若仍不能改善 log loss/Brier，则不支持这些特征的增量价值 |
| H2：基础生成偏向专家修复，导致过量修改 | 编辑规模远大于真实观测，保守提示也未消除差异 | 与真实下一修订训练目标对齐的强基线；生成阶段与选择阶段分别核查 | 同骨干 SFT、反馈条件 SFT、训练检索和补丁表示比较；若候选本身已接近幅度而选择仍过量，主要检查应转向排序 |
| H3：全文长度或评分集中程度混入 CD 差异 | 使用全文 sum-logp；位置分数与幅度代价方向不同 | 完整且合法的长度／幅度匹配和温度对照；不能凭相关性归因 | 所有方法共用长度处理与幅度控制，分开比较 argmax 与完整分布；若 CD 贡献只在未控制条件下存在，则不支持独立对比收益 |
| H4：相关修订候选支持不足 | 位置 oracle 远低于满分；部分真实改动零位置支持 | 内容与语义覆盖审查、训练修订生成器；强提示池缺同等 oracle | 固定排序比较新生成器支持；若支持提高而所选行为没有改善，单纯增加覆盖不足以解释总体失败 |
| H5：已有更好候选未被现有分数选中 | B 的多数记录有正位置选择损失 | 学习排序器强对照、完整分数与 copy 排名材料 | 共享池比较训练排序、基础分和 CD/B；如果训练排序或简单幅度控制解释全部收益，应降低当前公式的研究优先级 |
| H6：参考历史没有对齐能力或阶段，交互受残余混杂影响 | 长度／任务匹配有限，历史干预区间跨零，指派 seed 多数重复 | 预测时可见的阶段／失败状态匹配；信息公平的真实与参考历史对照 | 在共同结果概率和幅度下检验历史增量与反馈目标变化；若无稳定个体信息，不支持当前个性化交互主张 |

二组 A 只控制是否改动，不能单独限制改动后的幅度。完整进步分组是另一项待实现问题：必须先验收判题重放及隔离，定义编译失败、缺测与混合测试变化；不能把静态文本改动叫作进步，或把缺失判题结果当失败。
