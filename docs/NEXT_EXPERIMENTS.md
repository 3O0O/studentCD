# 下一阶段实验草案：结果概率、修订支持与反馈落实

日期：2026-10-03。状态：**供协作者讨论，尚未冻结；不构成新真实实验的启动授权。**

本文承接[研究概览](RESEARCH_SUMMARY.md)的负结果，提出可证伪的下一阶段计划。既有缓存重评分、历史干预、候选支持与静态 A 均已结束；本计划不要求重跑这些任务，不继承其预算、认证期限或运行许可。执行入口与资产边界见[复现说明](REPRODUCING.md)。

## 1. 从已有证据出发

已观察到的事实是：完整 70 条／17 名学生的开发队列上没有可靠 B 专属收益；静态 A 的固定主 q 未超过任务频率控制，A+CD 的期望位置 F1 点估计提高但区间跨零，同时编辑规模 CRPS 更差。模型经常比真实学生改得更多；文本不改动识别仍弱。工程验收完成不等于这些科学问题已经解决。

当前存在三个需要分开的瓶颈：

1. **概率预测**：能否预测学生这一步是否修改、将达到什么结果？
2. **生成支持**：候选池中是否存在接近真实局部修订、停滞或回归的程序？
3. **池内排序**：有了这些候选，方法能否选出或赋予它们合适的概率？

候选标签 oracle 只用于事后衡量支持与选择损失，不能成为推理选择器。上述瓶颈也不是互斥原因或已经识别的因果机制。当前缺少 copy 完整 likelihood／排名及强提示池 oracle 等诊断，不能凭已有聚合数值补写不存在的结论。

下一阶段拟检验的主问题是：**在相同结果概率和可比编辑规模下，真实学生历史与当前反馈是否仍改善具体下一修订预测；这种信息是否超过频率、保守编辑和直接学习真实修订的强基线？** 若简单控制或强训练基线解释了收益，就不保留旧 CD/B 公式作为必须成功的主线。

## 2. 共同数据原则与阶段交付

阶段按依赖排列，并非每做一个小片段就重新请求“继续”。一轮正式授权应覆盖冻结方案中逻辑完整的训练、生成、评价与复核；技术分批只用于恢复和记账。必要规模由可检验性决定，不为节约运行时间任意删学生、稀有类别、困难样本或必要对照。

| 阶段 | 要解决的问题 | 进入后续阶段前需交付的材料 |
| --- | --- | --- |
| Ⅰ：标签与 q | 不改动的定义是否可靠；个体特征是否超过频率？ | 完整标签／来源审查、训练内留学生与时间前推结果、预定 q 选择规则 |
| Ⅱ：生成与排序 | 是候选支持不足，还是排序失误；训练与补丁能否改善？ | 同骨干强基线、生成器×排序器比较、共同 q／幅度控制及成本表 |
| Ⅲ：安全判题与语义 | 能否可靠划分执行结果；是否落实实际反馈？ | 隔离与重放验收、结果组定义、盲标规则与可靠性报告 |
| Ⅳ：独立确认 | 开发阶段选择的机制能否泛化？ | 新独立数据、封存方案、完整确认结果及失败分析 |

阶段Ⅰ保留既有完整训练主范围 **737 条／140 名学生，其中 700 条改动、37 条不改动**。其他训练范围只能作为事前声明的敏感性分析；例如非空历史队列不能在结果不理想后替代主队列。70／17 是已见开发数据，不能作为新的确认性证据。

原 27 条 matched test 已有 copy 统计与 tokenizer 静态接触，若继续使用须准确披露为原留出评估，**不得称全盲或真正独立确认**。阶段Ⅳ需要另行核验并冻结未用于选模型、选权重、改指标或查看结果的新数据；优先公开且许可清楚的资源。若同源数据无法满足独立性，就寻找新的时间段、学生队列或公开数据源，明确相应泛化对象，不能以重新命名旧划分代替独立性。

## 3. 阶段Ⅰ：先审查 37 条不改动，再检验 q 的泛化

### 3.1 完整定义与来源审查

审查全部 737 条中的标签生成规则，并逐条核对 37 条不改动记录的来源、相邻关系和时间顺序。核对真实重复提交、提取／canonicalization 后相同、文件缺失、聚合重复、未观测下一提交是否被混为一类。未观测下一提交不能标成不改动；文本不改动也不能自动标成停滞或“没有学习”。

交付任务×学生×时间的改动频率、37 条负类的覆盖与集中程度、反馈缺失／类型及历史可用性审查。公共材料只发布聚合计数、定义与哈希，不发布学生正文或可追踪个体结果。若发现标签错误，应另建带变更记录的新数据版本；不得覆写原冻结数据或把更正后的队列冒充旧结果。

### 3.2 训练内设计

先明确泛化对象，至少分别评价：

- **留学生**：整个学生留出，训练与校准中不含该学生的监督标签；推理只能使用该查询时刻已经出现的历史。
- **时间前推**：按全局时间截止训练，再预测之后的提交；训练修订对的下一提交标签也必须在截止前已经形成，不能只检查当前提交时间。参考检索、特征标准化、校准和模型选择均只能使用截止前信息。新学生与已见学生后续提交分别报告，不混成同一估计对象。

内层选择与外层评价分开，超参数、特征筛选、频率平滑、校准器和决策阈值只由训练内层决定。需检查相邻修订对共享提交、同一历史进入多个样本、跨学生参考检索以及未来反馈的泄漏路径。折数、时间窗、边界共享提交处理与负类不足时的报告规则在读取外层结果前固定；不能随机拆提交后称留学生验证。

保留以下概率控制，使用相同可用信息和相同外层查询：总体改动频率、任务改动频率、当前状态特征、历史特征、反馈内容特征以及预定组合。任务频率的平滑和未知任务回退只能在训练内固定。反馈长度／字符数不是语义理解证据；反馈内容特征应对应可核查建议，历史残差应检验是否超过任务先验。

若使用负类加权或过采样，必须说明它改变训练先验，并在独立内层校准后检验原目标分布上的概率；加权分类准确率不能代替概率改善。少数负类折的覆盖、校准不确定性及学生内关联应完整报告，不通过丢弃负类、改变先验或只报整体 ECE 获得好看的结果。

**建议主端点**为等权学生宏 log loss，相对任务频率控制的成对差；Brier、稀有不改动类表现和分层校准为预定辅助端点。分类阈值指标与 AUROC／AUPRC只能补充，不能替代概率评价。最终选择哪个 q、允许哪些特征和模型搜索范围，仍须事前冻结；本草案不按已见 dev 改选 q。

## 4. 阶段Ⅱ：把生成支持与排序真正分开

### 4.1 建立任务对齐的强训练基线

建议在同一骨干上比较输入信息 `{当前题目与代码、加当前反馈、再加严格过去的学生历史}` 与输出表示 `{完整代码、局部补丁}` 的必要对照。训练目标都是预测实际下一修订，保留局部修改、真实重复提交、未修复错误和回归，不只挑成功修复样本训练。历史从查询前数据构建，不把真实下一代码放进提示。

这些 SFT 是本项目的任务对齐基线，**不是 ParaStudent、INSIDE 或 Conversational Serialization 的正式复现**。完整代码与补丁必须使用相同监督修订对；固定适配方式、训练随机种子方案、优化与模型选择预算，记录各自 token、步骤和真实成本。相同样本／步骤不等于相同训练 token，应事前决定主公平轴，并补足会改变结论的成本匹配对照。

补丁需冻结语法、坐标、应用规则与解析器，只能确定性应用到当前代码。非法、歧义、越界、重复或截断补丁均计入尝试并报告；不得按真实下一代码修复或补抽。评价还原后的完整程序，同时统计补丁有效率。完整代码与补丁的输出长度、提取与概率计算不同，不能直接混合两种表示的原始 sum-logp 排名。

共同保留 copy、未训练骨干 greedy、已冻结学生修订／保守编辑提示、任务频率 q 控制与训练检索基线。检索库只来自训练范围，查询特征和相似度在训练内固定。对历史信息、上下文截断、工具权限和候选预算的差别逐项记录；有意的信息消融需清楚标明。

### 4.2 生成器×排序器的交叉比较

每个生成器按预定预算在完整评价范围生成自己的池；对每个池应用同一组排序器，形成交叉表。排序器至少包含基础模型、固定 CD/B 历史对照、简单长度／编辑幅度控制；可增加训练内拟合的排序器。另在各来源的统一池上比较排序，以识别候选支持变化与选择变化。

原 861／743／318 池只用于已见 dev 的描述性诊断和协议检查，不产生新的确认性收益。新队列需新的、事前冻结的候选来源与尝试预算；真实下一提交不能加入推理候选。保留 raw、来源、规范化、去重与失败记录，共享 copy；重复与截断计尝试，不补抽。

所有全程序排序比较须使用共同的完整代码表示、EOS、提取、同分规则及评分信息。补丁生成器的还原结果可进入共同全代码池；若另研究补丁概率排序，应作为单独表示实验，不能把表示变化归因于 CD。

评价同时报告：候选 oracle、所选／分布期望质量、oracle−方法的选择损失、真实改动与不改动分层、修改幅度、来源占比和实际成本。oracle 依赖未来标签，仅是评价上界；静态 oracle 高并不证明语义候选充分。没有候选正文或对应评价时，指标标为缺失，不造强提示或 copy 的机制诊断。

### 4.3 共同 q 与组覆盖

比较 A+base、A+CD、A+B 和训练排序时，同一查询必须共享冻结 q、候选池、组定义和归一化规则。另比较仅 q、仅排序及二者组合，分开概率预测器贡献与组内行为贡献；编辑幅度控制不能只给新方法。具体幅度约束或惩罚只在训练内选定，不能在 dev 上追权重。

每个正概率结果组必须有有效候选。记录组覆盖、每组候选数与概率质量偏差；组缺失时不能删除该组后重新归一化 q，并继续声称控制相同结果概率。若采用按组生成、有限预算回退或判为不可实现，应在运行前冻结规则，所有尝试计入预算，且不能使用真实下一结果补组。不能只报告覆盖成功样本而隐藏完整队列上的失败。

文本二组的 copy 是不改动组唯一候选，因此该组没有排序改善空间。完整进步 A 将依赖阶段Ⅲ的可执行分组；在此之前不以静态二组代替“完成／改善／退步”。取 argmax 与从分布采样分别评价，不能由有限池组质量等于 q 推断 argmax 的输出频率也等于 q。

## 5. 阶段Ⅲ：安全判题前置与反馈语义评价

### 5.1 先验收执行环境与测试重放

学生程序与第三方判题脚本都是不可信代码。先用可信合成夹具验收隔离、禁网、文件访问边界、CPU／内存／进程／输出限制、截止和子进程回收；虚拟环境、tmux 或切换目录不足以提供隔离。验收通过并获得相应授权前，不执行真实学生代码或判题程序。

核对原作业测试完整性与版本，重放有已知判题记录的完整规定范围，保存测试条目、结果一致性和失配原因。零测试、缺测、运行失败和编译失败不能混为同一结果。只有可可靠重放的范围进入执行评价，其余记录保留在适用的静态行为评价并披露覆盖差异。

冻结完成、改善、不变、退步、混合变化及未知的规则，优先保存逐测试状态，而非仅总通过数。相同总分可能掩盖不同错误；结果组不代表知识掌握。候选选择／分组允许使用的测试，与最终独立泛化评价测试须分开；用过同一套测试选候选后，不得再称该测试结果为独立功能验证。

### 5.2 反馈落实与非目标修改

把实际反馈拆成可核查建议单位，分别标注可执行建议、说明／鼓励、歧义／错误建议与无法判断的内容。对真实下一代码及生成代码评价：是否尝试落实、是否正确落实、是否保留相关错误、是否引入非目标修改。文字复述反馈不算代码采纳，编译通过也不等于建议正确落实；未知不能直接记为未采纳。

先在训练材料上形成规则，封存后再评价独立队列。评审者看必要题目、当前代码和实际反馈，但不知道方法名／分数／研究预期；匿名化真实与生成修订顺序。主评价范围应完整覆盖事前定义的可评价建议，不挑“容易看出改善”的反馈。双人标注、分歧裁决、建议可评价率及一致性统计的范围提前固定。

若用自动裁判辅助，需在预定盲标范围核验其误差及方法偏差，不能只报告裁判自己给的分数。学生正文不发给未经授权的外部服务；费用与数据处理也不由本文授权。建议级宏 F1、正确落实率、非目标误改和未知覆盖率需与真实学生的落实模式联合解释，不能把更高修复率自动当更好的学生模拟，更不能称真实教学收益。

## 6. 指标包：每个指标只承担它能支持的结论

| 评价对象 | 建议指标 | 必须同时披露的边界 |
| --- | --- | --- |
| q 的结果概率 | 等权学生宏 log loss、Brier、分层校准 | 任务频率控制、稀有组覆盖、未知结果处理；粗 ECE 小不代表个体区分好 |
| 具体修订位置／操作 | 位置 F1、预定编辑操作 F1；分布方法报告期望值 | diff／token 定义固定；改动与不改动分层；文本位置不是语义正确性 |
| 编辑规模分布 | CRPS、预定分布距离与学生成对误差 | 与真实幅度比较；不可只报均值或只减少改动 |
| 反馈落实 | 盲核的建议级指标、正确落实和非目标误改 | 可评价率、歧义／错误反馈、裁判误差；不等同因果吸收或学习 |
| 执行结果 | 状态转移预测、独立测试结果及回归模式 | 选择测试与评价测试分开；覆盖、编译／超时／缺测单列 |
| 辅助代码相似性 | 精确匹配、CodeBLEU／AST／嵌入等预定补充 | 不据此确认学生正确性；不能只筛可解析／执行成功样本后比较 |
| 支持、稳定性与成本 | oracle／选择损失、覆盖、随机种子差异、token／实际时耗 | oracle 不可部署；尝试数、去重数与 GPU 成本不是同一公平轴 |

**期望位置 F1 不是整个代码行为分布的严格 proper score**：仅优化它可能奖励集中到某个候选，不能单独证明分布预测更准。q 的 log loss／Brier和编辑规模 CRPS检验的也只是相应结果／规模边际，需要与位置、操作、反馈和功能评价结合。

真实下一代码常不在有限候选池中，不能在排除了真值的池上伪造它的完整代码 log loss。若补充完整程序的 teacher-forced likelihood，应仅用于具有明确全程序概率的模型，并固定表示、tokenization 和长度报告；对比重评分未定义的全空间概率不能冒称相同指标。同一 q 下各 A 方法的组概率 Brier相同是构造性质，不算 CD 的额外收益。

## 7. 冻结主端点、比较家族与停止条件

阶段Ⅰ建议以 q 相对任务频率的学生宏 log loss差为主比较。阶段Ⅱ可保留共同 q／共同池下的期望位置 F1差作为组内行为主比较，同时将编辑规模 CRPS、误改和反馈非目标修改列为预定代价指标。阶段Ⅲ后的完整 A 需重新冻结执行结果组概率与条件行为端点，不能沿用二组名称偷换问题。

正式确认只选定一个事前定义的主要方法对照与科学主张；选择依据限于训练内验证，明确其相对最强任务对齐基线，而非只相对较弱提示。若有多个主问题或多组共同主要端点，事前定义比较家族、错误率和多重比较校正／层级检验规则；不得从多个池、q、模型、种子和指标里挑显著者作为主结论。

单位以学生为主，保留任务／时间结构；种子重复不是额外学生。置信区间、bootstrap或其他估计方法、重复次数、种子汇总与缺失处理在评价前固定。独立队列规模需由预定最小有科学意义的差异、学生聚类、稀有组支持和方差估计论证，不填没有依据的性能阈值，也不为方便缩到不足以回答问题的范围。

| 情况 | 预定处理原则 |
| --- | --- |
| 数据泄漏、标签定义错误或来源不可核验 | 停止相应科学比较，保留现场与旧结果，修正后作为新版本重新冻结 |
| 执行隔离／判题重放未通过 | 不开始学生执行；可继续已经授权的静态独立工作 |
| 正概率组无法覆盖或完整必要对照无法完成 | 报告不可实现／不完整；不能删样本、改 q 或缩减比较后标成功 |
| 资源／绝对截止、断线或未决预扣 | 按授权和账本停止依赖操作，保留尝试和失败，不自动续期、重启或补样本 |
| 主效应区间跨零、负向或对关键代价不利 | 报告证据不足或权衡；不按确认结果改权重追涨点，不把不显著等同无效证明 |
| 简单幅度控制／频率／强训练基线解释收益 | 不升级旧 CD/B 公式的有效性与新颖性主张；转向尚有区分力的机制假设 |

预算必须在启动前用合法的工程测量估算并冻结：训练、全部必要生成／评分、标注、验证及失败处理共用明确上限，记录模型加载、尝试、token与墙钟成本。此处不承诺未知时耗或成本；资源不足时先改研究范围并重新讨论，而非在结果出来后删对照。实验成功、预算结算与资源释放分别验收。

## 8. 近邻与尚未成立的贡献

以下沿用[研究概览已核验的一手入口](RESEARCH_SUMMARY.md#7-文献诊断与下一步)，用于讨论任务与机制对照，不表示已正式复现外部方法：

- [CoderAgent](https://arxiv.org/abs/2505.20642)：记忆与修改规划是强相关对照；意图／位置判别不能直接换算为本项目 diff F1。
- [ParaStudent v3](https://arxiv.org/abs/2507.12674v3)：直接学习真实修订并评价反馈相关行为；其数据、完整训练协议与报告值不等于本项目已有资产或结果。
- [Conversational Serialization](https://educationaldatamining.org/edm2026/proceedings/2026.EDM.short-papers.181/index.html)：轨迹训练及偏好优化需对齐数据和可执行评价，不能由提示控制冒称复现。
- [INSIDE](https://arxiv.org/abs/2608.10492)：联合推理与学生行动已有近邻。“先生成中间状态／推理再修订”不能作为原创模块；合成内心叙述不是真实心理监督。

SFT、补丁表示、知识／行动状态、分组归一化和对比公式都不能仅凭组合成为新意。可能有价值的贡献是证明某种可复现条件行为信息在共同结果概率、幅度和强基线下仍存在，并解释其适用边界；目前这仍是待证假设。更大模型或更多采样不保证收益，跨模型／跨数据验证应检验机制泛化，而不是寻找有利分数。

## 9. 冻结前需要协作者共同决定的事项

1. 不改动究竟按原文本还是冻结 canonical 文本定义；37 条审查是否需要新数据版本，哪些记录属于未知而非负类。
2. q 的目标人群、任务先验、留学生与时间前推划分、特征／模型候选、校准和内层选择范围；不按 dev 选择阈值。
3. SFT 输入×表示的必要完整对照、训练检索协议、同骨干版本、种子与样本／token／成本公平轴。
4. 生成器×排序器矩阵、共同池构建、补丁失败计数、共同 q、幅度控制与正概率组缺失规则。
5. 隔离验收负责人、测试完整性、重放标准、结果组定义与选择／独立评价测试范围。
6. 反馈建议单位、盲标与分歧规则、完整评价范围、自动裁判核验和允许的数据处理环境。
7. 真正独立确认数据的来源、许可、接触记录、划分及封存责任；原 27 条仅按已披露接触程度使用。
8. 一项主要科学比较、辅助与代价端点、多重比较方案、效应与规模论证、预算／截止／恢复规则，以及独立验证与资源释放门禁。

这些事项确定后，另存可核验的冻结协议与数据／代码版本，再申请适用的真实运行授权。当前材料交付的是讨论草案，尚未拟合新 q、训练模型、生成候选、执行学生程序或开展独立确认实验。
