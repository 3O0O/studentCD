# 工作目录与发布范围

本页说明当前研究代码、协作材料和本地资产的职责。正式 Git 仓库以 `student-sim-cd` 为根；本机旧探索、运行资产和运维记录继续保留在原位置。整理采用清晰入口与分类，不移动冻结产物或删除历史文件。

## Git 仓库结构

```text
student-sim-cd/
├── README.md                     研究入口和快速检查
├── CONTRIBUTING.md               协作方式和评测约束
├── pyproject.toml                包和可选依赖声明
├── .github/                      实验讨论和 PR 模板
├── src/student_sim_cd/           可复用研究实现
├── scripts/                      实验及独立复核入口
├── tests/                        合成测试和可选 CPU 模型检查
├── configs/                      冻结协议和历史环境观察
├── docs/                         原理 协议 结果 失败分析 计划
└── reports/                      经筛选的聚合数值与来源哈希
```

公开文档按用途分为：[研究概览](RESEARCH_SUMMARY.md)、[结果](RESULTS.md)、[失败分析](FAILURE_ANALYSIS.md)、[下一实验](NEXT_EXPERIMENTS.md)、[复现](REPRODUCING.md)，以及 [数据](DATA_PROTOCOL.md)、[推理](INFERENCE.md)、[上下文检查](PREFLIGHT.md)与[复制基线](BASELINE_REPORT.md)。建议新协作者先按 [CONTRIBUTING.md](../CONTRIBUTING.md) 阅读。

## 本机保留的内容

| 位置 | 用途 | 分享方式 |
| --- | --- | --- |
| `data/` | 原始公开数据及重建后的输入与标签 | 官方来源与构建协议，不随 Git 发布 |
| `models/` | 已核验模型和 tokenizer 资产 | 来源、实际版本、文件哈希；权重单独获取 |
| `outputs/`、`logs/` | 原运行、验收、失败记录和完整结果 | 聚合筛选进入 `reports/`，不原样提交 |
| `.venv/`、缓存、构建目录 | 本机依赖和临时运行文件 | 通过依赖声明重建 |
| `docs/STATUS.md`、`docs/RUNBOOK.md`、`AGENTS.md` | 本机现场记录和操作边界 | 本机留存；公开协作说明单独维护 |
| `docs/source-snapshots/` | 部署时制作的来源快照 | 保持封存，不随代码仓库公开 |
| 外层 `paperreading/`、`paperidea/` | 原文献笔记与历史 idea 探索 | 保留原位；当前研究的相关一手入口在公开文档引用 |
| 外层 `server-workflow/` | 个人机器连接、部署和监测 | 不进入研究仓库，也不作为协作者的认证方式 |

外层的 `idea.md` 与 `REQUIREMENTS.md` 是本地研究原件；公开文档提炼本项目的问题与要求，不静默替换原件。历史探索中不同任务的结果不合并成当前学生修订实验的证据。

## 新材料放在哪里

新协议放 `configs/`，以新文件记录数据范围、指标、选择规则及停止条件；既有冻结配置保持不变。新实验结果放新的 `outputs/` 子目录，先完成独立核验和分享审查，再将需要协作者讨论的聚合数值放到 `reports/`。结果说明链接到协议和相应代码版本。

`reports/` 的材料不含学生标识、逐样本或逐学生数组、代码正文、模型权重、个人连接信息和凭据；源文件哈希用于标明依据，不表示原产物已公开。机器可读聚合结果不能替代从私有原产物独立复算，也不能证明学生程序执行正确。

真实案例与逐样本派生数据需要单独确认分享范围和访问权限。测试标签继续与输入隔离，未见评测内容不用于共同讨论中的调参。需要真实计算资源的计划先明确授权与限额；目录整理不会恢复服务器认证或启动实验。

`.gitignore` 持续排除本机资产，但已跟踪文件不受新增忽略规则保护。每次提交都要检查实际 diff 和文件清单，不使用 `git add .` 将未知产物一并加入。
